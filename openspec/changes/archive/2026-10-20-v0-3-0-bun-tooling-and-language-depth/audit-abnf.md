# ABNF audit (task 2.1) — repro scripts in /tmp/abnfaudit/*.ts
## Bugs (verified unless marked)
1. HIGH parser.ts:168-170,125-128 — ExpressionParser.parse() never checks leftover tokens; first stray token silently ends the rule. `a = b ) c` / `a = b & c` / `a = "x" ]` / `a = b\n  c = d`: no syntax error, refs after the stop are lost (false "unused" hint on c, missed undefined refs). Fix: after parse, if tokens remain, emit Error "Unexpected <tok>" and keep scanning remaining Rulename tokens into references.
2. HIGH format.ts:117-118 + 242-243 — a column-0 comment inside a rule ends the rule; the indented continuation is then handled at top level, where the unknown `/` is dropped (line 243). `a = b\n; note\n    / c\n` -> `a = b\n; note\nc` (meaning changes, token lost). Fix: column-0 comment followed by an indented line should stay in the body; never drop top-level tokens (emit the raw line verbatim).
3. HIGH format-renderer.ts:223-235 — continuationIndent 0 (allowed by package.json:218, no minimum) with alternativeIndent=indent writes continuation lines at column 0. That is invalid ABNF and not idempotent (fuzz: `/ oncatenation = ...`). Fix: clamp to >=1 and add "minimum": 1.
4. MED format.ts:324, format-renderer.ts:364 — output always uses LF; CRLF input becomes LF. Fix: detect EOL (or use TextDocument.eol) and join with it.
5. MED format-renderer.ts:279-281,322 — empty alternatives are dropped: `true / / false` -> `true / false`, and `a = / b` loses the `/`. Formatter changes token streams. Fix: render empty alternatives as-is, or skip formatting rules that have parse errors.
6. MED diagnostics.ts:105-127 — any `=/` for a name suppresses the duplicate check: `a="x"\na="y"\na=/"z"` gives no warning. No diagnostic for `=/` with no base `=`, or `=/` before `=`. Duplicates are Warning, not Error. Fix: count rules with !isIncremental; >1 -> Error; =/ without an earlier `=` -> Warning/Error. Use rule.isIncremental, not a re-tokenize.
7. MED parser.ts:470-476,494-507,550 — a rule start requires `=` after the name, so the "needs = or =/" diagnostic is dead code. `a b`, `1abc = "x"`, `  foo = "x"` (indented, first line) are skipped with no diagnostic. Fix: diagnose any non-trivia token at top level (column 0) that does not start a rule.
8. MED parser.ts:68-83 — a column-0 non-rule line continues the previous rule (`a = b\nc\n`). RFC needs an indented continuation. Fix: Error "continuation line must be indented".
9. MED tokenizer.ts:171-230, parser.ts:395-427 — unterminated "..." or <...> gives no diagnostic, and slice(1,-1) drops the last char of the value. Also no check of char-val range (%x20-21/%x23-7E) or prose-val range. Fix: diagnostics in tokenizer/parser.
10. MED tokenizer.ts:280-309 — num-val is not validated: `%x` (no digits), `%x41-` (missing high bound), `%x5A-41` (lo>hi), `%xG1` (becomes %x + ref "G1"), `%q41` (Unknown, silent). All give no or misleading diagnostics. Fix: validate in the parser.
11. LOW parser.ts:297-335 — repetition `5*3` (min>max), `0*0`, and `3*` with no element give no diagnostic. Fix: Error for min>max and a missing element; Hint for 0*0 / 1*1.
12. LOW parser.ts:40-52 — precedingComment takes the previous rule's trailing inline comment (`a = b ; trailing\nc = d` -> c doc "trailing"). Fix: only use comments at column 0 on their own line.
13. LOW parser.ts:131-141 — definitionRange includes trailing newline and the next rule's doc comment (`a = b\n; doc\nc = d` gives a range ending at 1:11), so folding (folding.ts:27-31) spans lines it should not. Fix: end at the last non-trivia token.
14. LOW syntax-details.ts:6-7,13-14,286-320 — `%d1F` is matched as decimal (hex digit class used for every base). Inlay labels "range"/"sequence" fire on any `-`/`.` (`rule-name "."` -> "hex, range, sequence"). Hover runs regexes on the raw line, so `(` inside a comment shows "group delimiter". Fix: drive these from AbnfToken kinds.
15. LOW semantic-tokens.ts:122 — a user rule that redefines a core name (e.g. DIGIT) still gets the defaultLibrary style. diagnostics.ts:87 likewise never flags an unused user-defined ALPHA.
16. LOW word-at-position.ts:54-61 — the regex fallback lets rename/refs start from a word in a comment or string; that renames the rule. Fix: return undefined unless the position is on a Rulename token. (Found by reading; not run.)
17. CONFIG package.json:63 — abnf uses bnf-language-configuration.json, so ABNF gets `{}`, `'` autoclose, `/* */` blockComment, and a BNF wordPattern. abnf-language-configuration.json is dead but correct for ABNF. Fix: point the abnf language at it.
TextMate/snippets: scopes look right for ordering (leftmost match; identifier wins over digits in `rule2`). Snippets are valid. Not checked in an extension host.
## Performance
P1 semantic-tokens.ts:191-205 — selectSemanticTokens is O(n^2) (`selected.map` plus overlapsAny on every candidate): 1000 rules, about 12k candidates, took 128 ms. Fix: sort, then a sweep line or per-line last-end check.
P2 semantic-tokens.ts:72 + diagnostics.ts:26-46 — the full document is re-tokenized per call, beyond the cached parse. Fix: cache the tokens in GrammarWorkspace.get.
P3 parser.ts:474 — tokens.indexOf(token) per rule start: O(rules*tokens). Fix: pass the index.
P4 word-at-position.ts:86-107 — linear scan of all rules/refs per hover, definition, or rename. Fine now; index by line if needed.
P5 format-renderer.ts:506-531 — re-renders the whole line for each added token: O(k^2) per line.
## Missing features
Quick-fixes: `=` -> `=/` for duplicates, indent continuation line, insert missing `)`/`]`, swap range bounds, convert "x" <-> %s"x" / %x. Diagnostics for 1-11. Optional Hint suggesting %s"" when case matters. A formatter mode that refuses or keeps verbatim rules with parse errors. Recursion/cycle and unreachable-rule (not just unreferenced) analysis. Parse-error-aware semantic tokens.
